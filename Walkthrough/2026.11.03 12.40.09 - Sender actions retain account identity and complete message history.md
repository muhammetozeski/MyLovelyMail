# Sender actions retain account identity and complete message history

Source inspection showed that cached-only batch moves miss older server mail, IMAP FROM search
matches substrings, and local moves preserve MIME only when it is already cached. The combined
sender filing workflow therefore imports exact retained sender history first, downloads bodies
before local filing, rechecks the captured same-account destination, and then saves the sender
rule and invokes existing moves. POP3 scans sender headers without changing fetch limits; Fast
Mail uses its provider list, account message map and deletion operation gate.

Sender notification preferences reuse the filter action families and resolve above explicit
account, folder and application choices. Person statistics now parse exact recipient mailboxes
and follow message direction even after Sent mail is archived. Menus capture account identities
so later clicks do not follow a newly selected account.

See [the source-backed contract](../docs/SENDER-ACTIONS.md) and
[the fifty-idea decisions](../Brainstorm/Applied/2026.11.03%2012.40.09%20-%20Fifty%20sender%20and%20person%20action%20decisions.md).
The shared project compiled with these sender files. The concurrent filter verification reported
45/45 synthetic checks passing, including sender notification precedence and quick-rule reset
families. Live provider history transfers and native interaction remain outside that synthetic
verification; root coordinates application delivery with the other concurrent changes.
