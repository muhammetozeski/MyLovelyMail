# Workspace menu scope and reader navigation

The earlier shared-input checks covered compose fallback targets but missed blank workspace
context menus when a row was focused. `OpenWorkspaceMenu` reused `WorkspaceTargets` and passed
that inferred message to `OpenMessageMenu`, which changed selection. Workspace menus now
offer workspace actions independently of focus, reader state and bulk selection. Explicit row
and reader menus retain their existing targeting.

Reader links were constrained by `sandbox="allow-same-origin"`; ordinary anchors also lacked
a document target outside the frame. The document now declares a default external target and
permits popup/user-activated parent navigation, relying on the existing framework behavior.
No click interception or URL-opening code was added. See [the reader contract](../docs/DEVELOPMENT.md#mail-page-ownership).

Ten isolated checks passed for empty/focused/open-reader/bulk workspace states, real row
targeting, sanitized href preservation and rendered frame permissions. They verify source and
renderer behavior; native browser launch was checked against the framework source/documentation,
not by automating a click on the user's computer.
