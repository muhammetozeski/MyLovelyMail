# 2026.11.25 14:54 — Windows MAUI 10.0.110+ click fix, auto-maximize, and themed title bar

## What changed
1. **Windows WebView2 click blocking fix (`MyLovelyMail/MainPage.xaml.cs`):**
   - Isolated via A/B builds (`MAUI 10.0.20` / `10.0.70` vs `10.0.110` / `10.0.130`, `WindowsAppSDK`, plain `maui-blazor`, and host stripping) that `RootLayout.Add(trayIcon)` in `BuildTrayIcon()` blocked all real Win32 mouse input to `BlazorWebView` starting on `MAUI 10.0.110+` while synthetic CDP clicks still passed.
   - Changed `BuildTrayIcon()` to set `InputTransparent = true`, `WidthRequest = 0`, `HeightRequest = 0`, `HorizontalOptions = Start`, `VerticalOptions = Start`, and add the tray icon behind the WebView with `RootLayout.Insert(0, trayIcon)`.
2. **Automatic maximized startup and themed title bar (`MyLovelyMail/TrayService.cs`, `MainPage.xaml`, `MainPage.xaml.cs`, `wwwroot/index.html`):**
   - Opened the desktop window in real WinUI maximized mode (`OverlappedPresenter.Maximize()`) on normal start and on first restore from `--minimized` / `StartMinimized`.
   - Guarded `ClampToWorkArea` and debounced `SizeChanged` bounds saving so maximized windows are never pulled out of maximized state or saved as fake full-screen restored bounds.
   - Styled the window chrome via MAUI's `Window.TitleBar` + `AppWindow.TitleBar` caption button colors synced live to `ThemeManager` (`OnThemeChanged`), added the window icon (`trayicon.ico`), synced `MainPage.BackgroundColor` to `AppColors.BackgroundBase` (removing the undefined `PageBackgroundColor` resource), and updated `wwwroot/index.html` `<title>` to `My Lovely Mail`.

## Verification
- `61/61` `FilterChecks` passed; Windows Debug/Release, `MyLovelyMail.Web`, and Android Debug builds succeeded with 0 errors.
- Verified real Win32 mouse clicks (`SetCursorPos` + `mouse_event`) reach WebView2 (`⚙️ -> /Settings`, `🏠 -> /Mail`).
- Verified foreground screenshots show `IsZoomed = True` (`DWM = 0,0,1920,1020`), `0px` gaps at all edges, and a single theme-matched title bar.
