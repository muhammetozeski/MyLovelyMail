# Mail cleanup preserved presentation and corrected scoped reader caches

MyLovelyMail remains a shared Windows/Android MAUI application with a server-rendered Web preview. The maintenance cleanup is complete: oversized source files were divided by responsibility, unused template files were recycled, the unused WebAssembly head was removed, and developer entry points are in the documentation index. The Css.razor style system remains in place. The user did not connect a phone for this work.

The reader cached bodies, sender histories and conversations by message number alone. Synthetic folders and accounts using the same numbers demonstrated why the complete account/folder/message identity matters. Those caches and one-message image permission now use that identity; body loads also reject older generations. Shared folder operations own the busy guard before clearing cache, and counting or building folder trees no longer sorts or repeatedly scans whole collections unnecessarily.

Verification passed: the complete Release solution compiled with .NET SDK 10.0.400, 15 isolated renderer/storage regression checks passed, the original mail markup and style cascade were preserved, and all 101 development route labels were retained. A temporary Web preview returned the shared page and its moved reconnect script and stylesheet; that process was stopped. The last Android compiler review identified an unguarded Android 14 service type under an Android 11 minimum. Its version guard compiled in the final build; it has not been tested on a phone.

Use the [development guide](../docs/DEVELOPMENT.md) for source ownership and operation entry points. The local SDK selection for verification lived in the temporary test folder, not in the repository. A restore with SkipAndroidTargets excludes Android from the assets file; restore all targets again before building the whole solution.
