# Build counter, account folders, modal hierarchy, Fast Mail over Tor, and Direct-to-MX SMTP

## Context and observations

1. **Build Number & Commit ID**: `UpdateBuildInfo.ps1` runs before `MainProject` builds, incrementing `BuildInfo.BuildNumber` (seeded from the 49 prior GitHub releases) and recording the current short commit hash in `MainProject/Constants/BuildInfo.cs` and at the top of `AGENTS.md`. `AppConstants.AppVersion` formats `v<SemVer> (Build <N> · <hash>)`.
2. **Account Folders**: `AccountFolderStore` persists nested folders, sort order, and `IsExpanded` state in `UserData/account-folders.json`. The default `Main` folder uses the all-zero GUID `00000000-0000-0000-0000-000000000000` and cannot be deleted. Any empty or invalid `MailAccountData.FolderId` normalizes to `00000000-0000-0000-0000-000000000000`.
3. **Modal Hierarchy & Single Active Modal**: `CoreModal` previously inherited `ThemedComponentBase` directly, used a low-alpha surface (`AppColors.SurfaceStrong`), and clamped width to `400px` with centered text, making the Message Source modal transparent and cramped. Introducing `ModalBase : ThemedComponentBase` -> `CoreModal` -> `DialogModal` (`480px`), `WorkspaceModal` (`740px`), and `WideModal` (`1100px`) with opaque `AppColors.TooltipBackground` fixed readability and sizing. `ModalService` maintains a single foreground modal stack with `GoBack()` history, reusing `AccountWizard` in modal mode (`IsModal="true"`).
4. **Fast Mail & Strict Per-Account Tor Exit IPs**: `IncomingProtocol.FastMail` accounts (`GuerrillaMailProvider`, `MailTmProvider`) enforce `TorOnly = true`. `TorService.CreateIsolatedHttpClient` and `TorService.EnsureUniqueExitIpAsync` guarantee each Tor-enabled account uses distinct SOCKS5 credentials and a verified unique exit IP, rotating the circuit epoch on collision.
5. **Direct-to-MX SMTP over Tor**: When an account has no SMTP host (or is a `FastMail` account), `SmtpSendService` delegates to `DirectMxSmtpService.SendAsync`, which scrubs local machine/timezone headers, resolves MX records via DNS-over-HTTPS over the account's isolated Tor circuit, and delivers on port 25 using `StartTlsWhenAvailable` with plain-SMTP fallback and circuit rotation when an exit node blocks port 25.
6. **Managed Tor Lifecycle, Orphan Lock Cleanup & Directory Junction Resolution**:
   - Killing a running `MyLovelyMail.exe` instance bypassed `AppDomain.CurrentDomain.ProcessExit`, leaving its child `tor.exe` alive holding `AppCache/Tor/lock` and causing subsequent `tor.exe` starts to exit with code 1 (`It looks like another Tor process is running with the same data directory` / `Reading config failed--see warnings above.`).
   - `TorProcess` now serializes `StartAsync` with a `SemaphoreSlim`, binds child `tor.exe` processes to a Windows Job Object (`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`), persists `managed-tor.json`, cleans up any orphaned `tor.exe` holding `AppCache/Tor/lock` (with per-process directory fallback if locked externally), passes Scoop's `../data.original/geoip` files, and resolves directory junctions (such as Scoop's `current` junction) in `ResolveFinalExecutablePath` so process-path rules in `TorVpnForWindows` match the versioned binary.

## Verification

Compiled `MyLovelyMail.csproj` (`net10.0-windows10.0.19041.0`) and `MyLovelyMail.Web.csproj` (`net10.0`) with 0 errors. Extended `DebugApi` with `/fastmail/providers`, `/fastmail/domains`, `/fastmail/provision`, `/direct-mx/resolve`, `/account-folders`, and `/tests/fastmail` (`DebugApi.RunFastMailEndToEndSuiteAsync`), and executed all 7 end-to-end steps over Tor (managed Tor bootstrap + orphan cleanup, Guerrilla Mail provisioning, Mail.tm provisioning, Guerrilla Mail -> Mail.tm Direct-to-MX send and full MIME download, and Mail.tm -> Guerrilla Mail Direct-to-MX send and body download).
