# Android OCSP TLS fix, top-left nav toggle, and migration file picker

## Context
The Android build failed to connect to Gmail (and any mail server whose certificate chain lacks an OCSP responder URL), scoped storage prevented importing migration bundles from Downloads by raw path, the mobile `OnePane`/`TwoPane` grid overflowed horizontally, and the bottom navigation bar occupied vertical space for only two destinations (`Mail` and `Settings`).

## Observations & Decisions
1. **Android TLS revocation failure (`MailConnections.DirectRevocationCheck`):** Phone in-app logs showed `MailKit.Security.SslHandshakeException` with `Chain_RevocationStatusUnknown` and `Certificate does not specify OCSP responder`. Android's .NET revocation validator checks OCSP only (no CRL fallback). Added `MailConnections.DirectRevocationCheck = !OperatingSystem.IsAndroid()` and applied it to direct connections in `MailConnections.OpenAsync` and direct probes in `ConnectTriageService.ProbeWithAsync`. Chain, hostname, and expiry checks remain active; Windows retains MailKit's default revocation check.
2. **Removed bottom navigation & added `<AppNavToggle />`:** Deleted `AppBottomNav.razor` and `AppBottomNavCss.razor` (with user approval), removed `HasBottomNav`, `BottomNavHeight`, `ScrollBottomInset`, and `BottomNavigationItems` from `NavigationGenerator`, consolidated pane heights into `AppStyles.MailPaneHeight`, and placed `<AppNavToggle />` (`⚙️` on Mail, `🏠` on Settings) in the top-left of `MailSidebar` and `Settings`.
3. **Migration bundle picker (`UserFilePicker`):** Added `MainProject/Storage/UserFilePicker.cs` (bridged to MAUI `FilePicker.Default.PickAsync()` in `MauiProgram.cs`) and a `📂 Choose file` button in `Settings.razor`, plus an immediate `SyncScheduler.SyncNowAsync()` kick after import.
4. **Mobile horizontal overflow (`MailResponsiveCss.razor`):** Switched `1fr` grid tracks under `TwoPane` and `OnePane` to `minmax(0, 1fr)` so the horizontally scrolling account/folder strip no longer pushes the search bar and action toolbars past the phone viewport.

## Verification
- **Automated & Multi-Target Builds:** `61/61` `FilterChecks` passed; `MyLovelyMail` (Windows Debug/Release + Android arm64 Release APK) and `MyLovelyMail.Web` built with `0` errors.
- **Windows Visual & Interactive (`DebugApi`):** Verified `AppNavToggle` renders top-left on Mail (`⚙️`) and Settings (`🏠`), switches routes cleanly in both directions, and no `.bottom-nav-container` exists.
- **Real Phone Runtime Verification (Android 15 arm64 via ADB):** Exported all 8 PC accounts via `MigrationService.ExportBundle` from a temporary copy of `UserData`, imported on phone via `📂 Choose file`, verified `Bundle imported — accounts, settings and passwords restored.`, verified `0` SSL/certificate errors in `logcat`, verified Gmail warning icon disappeared and `INBOX` messages loaded cleanly, and verified zero horizontal clipping on the mobile screen.
