# Shared menus and mouse triage

The input feature uses one menu host and the existing mail/storage owners; see
[the input contract](../docs/DEVELOPMENT.md#shared-input-and-message-identity).
Mail commands resolve complete account/folder/message keys and expand existing conversation
groups. Side buttons, quick actions and bulk toolbars share one command/error boundary.
Mouse 5 is DOM button 4 (front/read); Mouse 4 is DOM button 3 (Trash). Non-mail and editing
surfaces have contextual fallbacks rather than browser navigation.

Cross-folder search exposed an ownership problem in moves: the same summary was briefly stored
under two folders while its number was reassigned, so a change subscriber could fail building a
dictionary before source removal. The single cache-move path now copies metadata, writes the
destination MIME/index, then removes the source. Server moves retain their source until confirmed;
pending rows are hidden and duplicate requests are rejected. Local Trash never inherits permanent
deletion, and POP3's known incoming numbers include local filing.

Verification: 36 isolated C# service/renderer checks and 33 JavaScript dispatch/geometry checks
passed, including source/target collisions, MIME preservation, bulk selection, owner repaint,
failure paths, previous folder restrictions and sandboxed preview input. The shared and Web
builds passed with the existing dependency-audit and UiCulture warnings. Source is stamped
1.42.0 for Windows/Android package delivery; these checks are not native-device interaction tests.
