# Startup null crash recovery and deterministic sorting across all surfaces

## Context
Users reported repeated `AppErrorBoundary` `NullReferenceException` crashes on startup and interaction, `⚡ Reload App` reopening the same broken state instead of returning to a clean Mail view, and broken sorting/reordering across mail folders, accounts, account folders, toolbars, and message/sender lists.

## Observations & Root Causes
1. **Boxed `default(MailMessageIdentity)` startup crash (log + source evidence):** Decoded `AppCache/Logs` showed 24 identical `NullReferenceException` stack traces at `MessageStore.FolderKey` <- `MessageStore.GetSummary` <- `Mail.ResolvePrimaryMessage` <- `Mail.ResolveToolbarAddedAction` <- `UiCustomizationStore.ApplyLayout`. Because `MailMessageIdentity` is a `readonly record struct`, `targets.FirstOrDefault()` on an empty `MailMessageIdentity[]` returned `default` (`AccountId = null`, `FolderFullName = null`, `Uid = 0`), which implicitly boxed into a non-null `MailMessageIdentity?` and bypassed `explicitLead is { } lead`. In addition, `ResolveToolbarAddedAction` and `ResolveMenuAddedItem` lacked cases for promoted `Account.*` (such as `"Account.CopyEmail"` in `SidebarFolderHover`), `Folder.*`, and `AccGroup.*` actions.
2. **Error recovery looping back into broken state (source inspection):** `AppErrorBoundary.HandleReload()` called `NavManager.NavigateTo(NavManager.Uri, forceLoad: true)`, reloading the failing URL with stale drag/menu/modal/open-message state still intact.
3. **Sync overwriting custom folder `SortOrder` (source inspection + runtime test):** `ImapSyncService.SyncOpenedFolderAsync`, `FastMailSyncService.SyncAccountAsync`, and `Pop3Service.SyncAccountAsync` constructed new `MailFolderData` instances without copying cached `SortOrder` or `IsExpanded`, resetting reordered folders to `SortOrder = 0` as soon as a folder was clicked/synced. `MessageStore.ReorderFolder` also built the folder tree with `respectCollapsed: true`, omitting collapsed subfolders during renumbering.
4. **Pointer bubbling and hit-zone defects in drag reordering (source + `DebugApi` verification):**
   - `ActionSlot` did not stop propagation of `pointermove`/`pointerup` while `ActionDragService.IsDragging` was active, causing parent `CustomizableActionBar` to overwrite the hovered slot index with `visibleIds.Count` (end of bar) on every move.
   - `UiCustomizationStore.Reorder` replaced `OrderedIds` with only currently mounted `currentVisibleIds`, dropping conditional unmounted buttons to the tail when they reappeared.
   - In `MailSidebar`, child elements (`<CoreChip>`, hover action bars) reset `PointerEventArgs.OffsetY` near `0`, `HoverAccountFolder` used a `34px` height estimate on a `28px` header (leaving almost no bottom `After` zone and causing accidental `Into` nesting), adjacent sibling rows had a 50% no-op zone (`Before` on `i + 1` or `After` on `i - 1`), and `End*PointerAsync` re-evaluated `Hover*` on `pointerup`.
   - Releasing a mouse button outside the window left `hasCandidate` armed in `WorkspaceDragService`/`ActionDragService` until guarded by `(e.Buttons & 1) == 0` on global `pointermove`.
   - `<Virtualize>` in `Mail.razor` lacked sort-keyed `@key` attributes, keeping stale row slots when sort direction/field changed; `AccountStore.Move` swapped across different `AccountFolder` groups; `FilterRules.razor` did not subscribe to `FilterRuleStore.OnRulesChanged`.

## Decisions & Outcomes
- Added `MailMessageIdentity.IsValid`, defensive null/empty guards in `MessageStore`, safe `targets.Length > 0 ? targets[0] : null` handling, full `Account.*` / `Folder.*` / `AccGroup.*` resolution in `Mail.razor.ActionsCatalog.cs`, and `try/catch` isolation around `resolveAdded` in `UiCustomizationStore.ApplyLayout`.
- Added `MailUiState.ResetTransientFailureState()` and updated `AppErrorBoundary` so both `Try Again` and `Reload App` clear active drags/menus/modals, save any active draft, sanitize selection state, and navigate to `/`.
- Preserved `SortOrder` and `IsExpanded` across `MessageStore.SaveFolder`, `ImapSyncService`, `FastMailSyncService`, and `Pop3Service`; updated `MessageStore.ReorderFolder` and `FolderTreeService` to enforce same-parent sibling reordering and move full subtrees with `respectCollapsed: false`.
- Fixed `ActionSlot`, `UiCustomizationStore` (`MergeOrderedIds`), `ActionDragService`, `UiCustomizerModal`, `ListFilterWindow`, `WorkspaceDragService`, `MailSidebar`, `MainLayout`, `AccountStore.Move`, `AccountFolderStore.GetRootFolders`, `Mail.razor` (`<Virtualize @key>`), `Mail.razor.cs` (tie-breakers and sender list filters), `FilterRules.razor`, `MailTmProvider` (HTTP 429 backoff + warning-level per-attempt logging + `UnauthorizedAccessException` on 401), and `ResiliencePolicy`.
- **Verification:** `61/61` `FilterChecks` (including new crash/reorder regressions) and `79/79` `AnonymityChecks` passed; `DebugApi` background visual and interactive verification confirmed zero `AppErrorBoundary` crashes with the user's `ui-layout.json` and `account-folders.json`, accurate drag reordering of folders, accounts, and toolbar buttons, and live `<Virtualize>` sort/search updates.

## Implications for Next Work
- Never pass `FirstOrDefault()` of a value-type identity struct into a nullable struct parameter without checking `.IsValid` or collection length first.
- Any new sync provider calling `MessageStore.SaveFolder` must preserve `SortOrder` and `IsExpanded` (also enforced defensively inside `SaveFolder` when incoming `SortOrder == 0`).
