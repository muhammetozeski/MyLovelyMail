# Provider pagination and complete MIME before future local filing

Source inspection found two completeness gaps in the full sender workflow: Fast Mail lists stopped
at page one, and future IMAP/POP3 rule moves could file only a lightweight summary into a local folder.

Mail.tm now follows native Hydra next links, validating HTTPS origin, port, message-list path and page
query before authentication. Guerrilla Mail advances its native offset using returned page lengths and
the total count. Both retain the existing isolated Tor client for the operation, deduplicate remote ids
and reject pagination with no progress. The Tor HTTP client already disables automatic redirects.
The native metadata is documented by [Mail.tm](https://docs.mail.tm/api/messages) and
[Guerrilla Mail](https://www.guerrillamail.com/GuerrillaMailAPI.html).

Future IMAP/POP3 local rule filing now downloads missing MIME through the existing open session,
atomically caches it and only then moves the cached message. A fetch/save failure propagates before
the source is removed. Parent-owned FastMailSyncService needs the equivalent provider-direct hook
inside its operation gate; recursively calling its gated download operation would acquire that gate
twice. The sender-workflow documentation owner received this contract for integration.

Evidence here is source inspection and a clean `git diff --check`; the parent task owns compilation
and native review. No real mailbox was accessed for this work.
