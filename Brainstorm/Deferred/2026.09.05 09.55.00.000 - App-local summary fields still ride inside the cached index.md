# App-local summary fields still ride inside the cached index

Kategori: data-integrity | Efor: L | Rank: 3

## Ne
The second half of "Storage location follows recoverability, not the writing class". The first
half shipped: local folders (Drafts, Outbox, Sent and anything a rule or the user made) now live
under UserData, and deleting UserCache no longer loses them - verified by deleting the whole
UserCache folder and finding the draft still there.

What is still in the cache is the app-local FIELDS that ride inside `index.jsonl` of SERVER
folders, where they sit in the same rows as the synced data:

- `MailMessageSummary.Tags`
- `MailFlags.Important` (64)
- `MailFlags.Muted` (128)
- `MailMessageSummary.SnoozedUntilUtc`

None of these exists on any server, so deleting UserCache loses them while the mail itself comes
back on the next sync.

Splitting them means a sidecar file per server folder under UserData - keyed by uid - written by
`MessageStore.SaveIndex` and merged back in `MessageStore.LoadIndexFromDisk`, plus a migration
that lifts the existing values out of every cached `index.jsonl`.

## Neden ertelendi
Not because it is unclear, but because the cost and the risk do not match the loss.

Every write path in `MessageStore` - `UpsertSummaries`, `SetSeen`, `RemoveMessages`,
`ClearFolderCache` - would have to keep two files in step, and any gap between them produces tags
attached to the wrong message rather than an obvious failure. That is a subsystem change, and the
loop's rule is to park core changes whose blast radius is wide.

And the loss it prevents is annotation, not content: a user who deletes UserCache gets all their
mail back and has to re-tag and re-snooze. The half that shipped is the one where deletion
destroyed something no server could return - a draft the user wrote, or a message already sent.

## Ne zaman yapmali
When something else forces `index.jsonl` to change shape anyway, so the migration and the
two-file discipline are paid for once instead of twice. Until then the honest position is the one
now written in the `MessageStore` class summary: UserCache holds mail that re-syncs, and the
annotations on it are lost with it.
