# Move picker gains local-folder targets (works on POP3 too)

Kategori: folder-operations | Efor: S | Rank: 2

## Ne
In MainProject/UI/Pages/Mail.razor.Interaction.cs, change MoveTargets (currently returns [] unless the account is IMAP and the open folder is a server folder, and filters '!f.IsLocal'): for IMAP server folders offer all other folders (server + local); for POP3 accounts or when the open folder IsLocal, offer only local folders (server targets stay excluded from local/POP3 sources — no upload path exists). In BulkMoveTo, branch on targetFolder.IsLocal: call a new bulk helper MessageActions.MoveToLocalFolder(account, folderFullName, summaries, localName) in MainProject/Services/Mail/MessageActions.cs that loops MessageStore.MoveToLocalFolder per uid; for IMAP server sources leave the server copy untouched (matches the 'local folders are this machine only' design, and sync's LastSeenUid range fetch in ImapSyncService means the message is not re-downloaded). The existing server-target path stays as is. In Mail.razor's move-picker @foreach add a '📁 Local' divider separating local targets. Verify via a /move (or extended bulk-action) endpoint in MainProject/zTests/DebugApi.cs driving the same service call, per the no-screen-clicks rule.

## Neden
Local folders exist and rules can fill them, but a human triaging the inbox cannot put a message into one by hand — and POP3 accounts have no Move button at all. Verified in code: MoveTargets at Mail.razor.Interaction.cs:114-118 excludes local folders and POP3 entirely, while MessageStore.MoveToLocalFolder (MessageStore.cs:219) already performs the complete local move including .eml carry-over, and ImapSyncService's LastSeenUid-based fetch makes the leave-server-copy approach safe. One property change plus one small helper turns the already-shipped move picker into real manual filing.
