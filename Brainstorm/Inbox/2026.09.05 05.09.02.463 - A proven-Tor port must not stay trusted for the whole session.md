# A proven-Tor port must not stay trusted for the whole session

Kategori: protection | Efor: S | Rank: 1

## Ne
TorService.IsProvenTorAsync returns the remembered verdict before anything else, and positive
verdicts are cached by "host:port" for the life of the process. The fast path in
RequireEndpointAsync re-checks only that something still speaks SOCKS5 there. Neither
forceRediscovery (ladder rungs 4/5) nor anything else clears a true verdict.
Fix: give a positive verdict an expiry (store the time with it) and re-run the RESOLVE check when
it is older than a few minutes; drop the cached verdict entirely when forceRediscovery is asked
for. Negative verdicts can stay cached - a port that proved it is not Tor is worth remembering.

## Neden
Tor Browser is open, 9150 passes the check and is cached. The user closes Tor Browser and later
runs `ssh -D 9150 somehost` in the same app session. The next connection of the Tor-only account
passes the SOCKS5 greeting, hits the cached true, and its server name goes to that proxy - which
resolves and connects to it outside Tor - while the log says "routing through 127.0.0.1:9150".
