# Force-resync a folder: reset LastSeenUid and refill from scratch

Kategori: recovery | Efor: S | Rank: 2

## Ne
Add `MessageStore.ClearFolderCache(accountId, folderFullName)`: remove the folder's entry from the `Indexes` dictionary (required — `GetIndex` caches a `FolderIndex` behind a sticky `Loaded` flag, so deleting only the file would leave stale summaries in RAM), delete `index.jsonl` and the `Messages/` directory under `FolderCachePath`, re-`SaveFolder` the existing `MailFolderData` with `LastSeenUid = 0` while keeping `Role`, `DisplayName` and `UidValidity` (keeping UidValidity matters: `SyncOpenedFolderAsync`'s check at lines 182-186 then stays quiet and the plain `lastSeenUid == 0` first-fill branch runs), then raise `OnFolderChanged`. Add `ImapSyncService.KickFolderResync(account, folderFullName)` that calls it and then goes through the existing `KickFolderSync` path — no new fetch code, the folder repaints in `FirstFillSliceSize` (50) slices. For POP3, clearing the INBOX cache empties `Pop3Service.SyncAccountAsync`'s `known` set, which is exactly its `isFirstSync` path and correctly suppresses the notification burst. Surface it as a hover-revealed resync control on the folder row in `Mail.razor` — note `mail-folder` is itself a `<button>` (line 69), so the control needs a sibling inside a wrapper div, not a nested button. The existing "Fetching this folder from the server…" block (lines 120-128) covers it unchanged, since the cache is empty and `IsFolderSyncing` is true for this path. Add `POST /resync?accountId=&folder=` to `DebugApi`. Scope it honestly in the UI text: the refill restores the newest `InitialFetchCount` (300), not the entire folder.

## Neden
Every IMAP fetch after the first is `new UniqueIdRange(new UniqueId(lastSeenUid + 1), UniqueId.MaxValue)` (ImapSyncService.cs:209), so anything that truncates or corrupts a folder's cache is permanent — the client never looks at or below `LastSeenUid` again. The only existing reset is the UIDVALIDITY branch inside `SyncOpenedFolderAsync`, which no user action can reach. One store method plus a button turns a dead-end into a click, and it verifies end-to-end with no external service beyond the already-configured account: `GET /messages` count, `POST /resync`, `GET /messages` count restored.
