# DebugApi has no Origin or Host check, so a visited web page can drive it

Kategori: protection | Efor: S | Rank: 2

## Ne
DEBUG-ONLY, and that was confirmed rather than assumed: DebugApi.Start() sits inside #if DEBUG in
MauiProgram, the script bridge is #if DEBUG in MainPage, and Export.ps1/Publish.ps1 both publish
-c Release. The deployed install listens on nothing. So shipped users are NOT exposed - this is a
developer-machine issue.

On a Debug build the handler answers any request: HandleAsync/RouteAsync never look at Origin,
Referer or Host. A page the developer visits can fire
fetch("http://127.0.0.1:52539/exit", {method:"POST", mode:"no-cors"}) to kill the app, POST /trim
to drop cached bodies, POST /settings/set (query-only, no preflight), or POST /dom/script with a
text/plain body that RenderedPageProbe.RunScriptAsync runs as JS inside the privileged WebView.
CORS hides the responses cross-origin; DNS rebinding removes even that and makes /messages,
/message, /source, /logs and /export readable.

Measured: an HttpListener bound to http://127.0.0.1:52539/ accepted raw requests carrying
Host: evil.attacker.com, Host: localhost:52539 and Host: 127.0.0.1:52539 - http.sys does not
reject a foreign Host for an IP-literal prefix, so binding to loopback is no defence by itself.

Fix: reject any request whose Host header is not 127.0.0.1:52539 (or [::1]), and any request that
carries an Origin or Referer header at all - a test harness sends neither, a browser page always
sends one. Both checks belong at the top of HandleAsync, before RouteAsync.

## Neden
The port is opened on a machine the developer browses the web from, and one of its routes runs
arbitrary JavaScript inside the app WebView. Two header checks close it, cost nothing, and cannot
break a script client.
