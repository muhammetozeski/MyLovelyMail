# Attachment reminder that ignores the quoted history

Kategori: Compose quality | Efor: S | Rank: 2

## Ne
Mail.razor.Compose.cs:28 QueueActiveDraftSend() hands the draft straight to OutboxService.Enqueue with no checks, so 'ekte gonderiyorum' with an empty draft.AttachmentPaths goes out as-is.

New MainProject/Services/Mail/AttachmentIntentService.cs with one pure method, `static string? FindTrigger(string subject, string body)`. It scans the subject plus only the NEW part of the body -- stopping at the first line matching the quote shape MailBodyRenderer.PlainQuoteStart() already ships (`^\s*(>|-{2,}\s*Original Message\s*-{2,}|On .{0,160}\bwrote:\s*)$`, MailBodyRenderer.cs:105, verified verbatim) and skipping any `> ` line -- against a word list covering both languages the user writes in: attached, attaching, attachment, enclosed, 'see the file', CV, resume, ekte, ektedir, ekli, ekleyerek, ilistir. Match case-insensitively and WITH word boundaries, not Contains: bare substring matching makes 'CV' fire inside 'service' and 'ekli' inside 'eklinde', which is exactly the false-positive rate that trains the user to ignore the bar. Return the matched word so the warning names it instead of nagging generically.

In Mail.razor.Compose.cs add `string? AttachmentHint { get; set; }`. QueueActiveDraftSend() returns early setting AttachmentHint when `draft.AttachmentPaths.Count == 0` and FindTrigger hits; a `ForceQueueActiveDraftSend()` clears it and runs the existing body (SaveDraft / CloseCompose / Enqueue). Clear AttachmentHint in OnComposeFilesSelectedAsync (line 71) and DiscardCompose (line 130) so attaching a file dismisses the bar by itself. In Mail.razor render the bar above the `mail-compose-actions` div (line 330), styled off the existing `.mail-undo-bar` rules (MailCss.razor:787): the matched word, a 'Send anyway' button calling ForceQueueActiveDraftSend, and a label reusing the same InputFile as the `mail-compose-dropzone` (Mail.razor:307).

Verify with no clicking and no network: add `GET /attachment-hint?subject=&body=` to zTests/DebugApi.cs returning `{ trigger }`. Body 'ekte gonderiyorum' returns 'ekte'; body '> ekte bulacaksiniz' returns null; body 'bu serviste' returns null (word-boundary check); a forward whose quoted original says 'please see the attachment' returns null while the same words typed above the `On ... wrote:` line return the word. That last pair is the whole point of the feature and is checkable from curl alone.

## Neden
The forgotten attachment is the one compose mistake that cannot be undone once the 5-second UndoSendSeconds window closes, and this client makes it easier to hit than most: BuildReply and BuildForward prepend the quoted original (ComposeService.cs:148,165), so a naive keyword scan would fire on every reply to a message that itself mentioned an attachment. Skipping the quoted region with the regex MailBodyRenderer already ships is what keeps the warning rare enough that the user still reads it. Chosen over the DefaultComposeFormat wiring because it is one pure function with an offline curl proof, while that one needs a live SMTP round trip to verify and would silently flip every existing send to multipart, since the enum already defaults to Html.
