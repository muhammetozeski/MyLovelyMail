# SendGuardService: one pre-send checklist bar instead of the lone attachment hint

Kategori: compose-safety | Efor: M | Rank: 1

## Ne
Add `MainProject/Services/Mail/SendGuardService.cs` with `public static IReadOnlyList<SendWarning> Inspect(ComposeDraft draft)` and `public readonly record struct SendWarning(string Code, string Text)`. All checks pure, computed from the draft plus `ContactIndexService.Suggest(account.Id, take: 200)`: (a) `no-subject` when `string.IsNullOrWhiteSpace(draft.Subject)`; (b) `many-recipients` when parsed To+Cc count crosses a const threshold — ComposeService.cs:151-157 fills `draft.Cc` from `summary.ToAddresses` with no ceiling, so one Reply-all on a 40-person thread silently addresses 40 people; (c) `duplicate-recipient` when the same address is in both To and Cc; (d) `domain-typo` when a recipient's domain is edit-distance 1 from a contact-index domain — tightened from the proposal: only fire when the known domain appears at least a few times in the index AND the typed domain appears zero times, otherwise `company.co` vs `company.com` warns on every legitimate new correspondent; (e) `attachment` by calling the existing `AttachmentIntentService.FindTrigger(draft.Subject, draft.Body)`, so the shipped check becomes one row of the list rather than a parallel mechanism. In `Mail.razor.Compose.cs` replace the `string? AttachmentHint` field (line 29) with `List<SendWarning> SendWarnings`; `QueueActiveDraftSend()` fills it and returns when non-empty, `ForceQueueActiveDraftSend()` clears it and sends — also clear it in `OnComposeFilesSelectedAsync` and `DiscardCompose` where `AttachmentHint = null` sits today. In `Mail.razor` the `mail-undo-bar mail-undo-bar--warning` block (lines 378-386) renders one row per warning, keeps the InputFile button only on the `attachment` row, keeps one Send-anyway wired to `ForceQueueActiveDraftSend`. Verify with a new DebugApi case beside `GET /attachment-hint` (DebugApi.cs:523): `("GET", "/send-check")` reading accountId/to/cc/subject/body from the query and returning the warning codes.

## Neden
Compose blocks exactly one mistake today and ships the other three to the server. Empty-subject and reply-all-blast are unrecoverable once SMTP accepts them, and undo-send only buys `UndoSendSeconds`. `AttachmentIntentService` plus the warning bar already prove the shape works and the user tolerates it, so this reuses both instead of adding a second warning surface. Every check is a pure function of the draft, so the whole feature is exercised over 127.0.0.1:52539 with no screen interaction — unlike the send-later idea, whose past-due half needs a live SMTP account.
