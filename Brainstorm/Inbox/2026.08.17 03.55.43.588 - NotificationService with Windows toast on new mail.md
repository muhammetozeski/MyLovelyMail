# NotificationService with Windows toast on new mail

Kategori: notifications | Efor: M | Rank: 30

## Ne
New static MainProject/Services/NotificationService.cs. ImapSyncService/Pop3Service report each newly downloaded MailMessageSummary to NotificationService.OnNewMessages(account, messages) at the end of a sync pass (after the incoming rule pass, so the Muted flag and rule sounds are already applied). The service checks Settings.NotifyOnNewMail, skips messages with MailFlags.Muted, skips when now is inside Settings.QuietHoursStart/QuietHoursEnd, then raises one Windows toast (Microsoft.Windows.AppNotifications from the WinAppSDK already bundled with MAUI; behind #if WINDOWS via a small partial in the MyLovelyMail head project next to TrayService) showing sender + subject, or 'N new messages' when a batch arrives. Sound: play the per-message sound name (rule SetNotificationSound action result, falling back to Settings.NotificationSound) from Resources/Sounds via Windows.Media SoundPlayer; 'none' silences. Toast activation calls TrayService.ShowMainWindow() and MailUiState.SelectAccount/SelectFolder + OpenMessageInReader for the clicked message.

## Neden
The settings (NotifyOnNewMail, NotificationSound, QuietHours) and rule actions (Mute, SetNotificationSound) are all shipped and stored but nothing consumes them yet — new mail is currently invisible when the app sits in the tray. This closes the loop with no new dependencies.
