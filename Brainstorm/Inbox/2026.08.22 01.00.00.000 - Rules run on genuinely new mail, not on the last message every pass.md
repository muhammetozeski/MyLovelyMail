# Rules run on genuinely new mail, not on the last message every pass

Kategori: correctness | Efor: S | Rank: 1

## Ne
`ImapSyncService.SyncOpenedFolderAsync` artımlı dalda şunu yapıyor:

    var range = new UniqueIdRange(new UniqueId(lastSeenUid + 1), UniqueId.MaxValue);
    var fetched = await folder.FetchAsync(range, SummaryItems, cancellationToken);
    foreach (var item in fetched)
    {
        ...
        if (item.UniqueId.Id > lastSeenUid) newCount++;
    }
    ...
    if (lastSeenUid > 0 && summaries.Count > 0 && !backgroundRefresh)
    {
        MuteService.ApplyToIncoming(summaries);
        ruleResult = RuleEngine.ProcessIncoming(account, folder.FullName, summaries);
        MessageStore.UpsertSummaries(account.Id, folder.FullName, summaries);
    }

IMAP'te `<n>:*` aralığı, n kutudaki en yüksek uid'den büyük olsa bile **her zaman son mesajı**
döndürür (RFC 3501). Yani yeni mail yokken bile `fetched` bir eleman içerir. `newCount` bunu
doğru sayıyor (0), ama kural kapısı `newCount` yerine `summaries.Count` bakıyor. Sonuç: kutunun
son maili her senkron turunda yeniden kurallardan geçiyor.

Kanıt (kullanıcının 22.08.2026 log'u ve rule-audit.jsonl):

    IMAP folder 'INBOX': fetched 1 summaries (0 new), server count 1461
    [Error] Rule move to 'YedeklemeRapor' failed: The requested folder could not be found.   <- 48 kez
    rule-audit.jsonl: aynı (MessageId|RuleId|Action) üçlüsü 16 kez kayıtlı
    1548 kayıttan yalnızca 516'sı farklı

Düzeltme: kural/mute/upsert kapısı `newCount > 0` olacak ve `ProcessIncoming`'e yalnızca
`s.Uid > lastSeenUid` olan özetler gidecek. Kapıyı geçen aynı listeyi bildirim yolu da
kullanıyor, o yüzden tek bir `arrived` listesi hesaplanıp her iki yerde de o kullanılmalı.

## Neden
Bu tek satır dört ayrı görünür arızanın kaynağı: okuyucudaki kural rozetleri kendini
tekrarlıyor, başarısız bir taşıma sonsuza dek yeniden deneniyor, MarkRead/Mute/SetNotificationSound
her turda yeniden uygulanıyor ve rule-audit dosyası (515 KB) her kayıtta baştan yazıldığı için
disk ile CPU boşuna harcanıyor. Uid tabanlı artımlı senkronda "getirilen" ile "yeni" aynı şey
değildir; bu ayrım tek yerde değil, kapının kendisinde durmalı.
