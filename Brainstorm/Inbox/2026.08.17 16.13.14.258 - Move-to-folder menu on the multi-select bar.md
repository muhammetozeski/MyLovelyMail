# Move-to-folder menu on the multi-select bar

Kategori: folder-operations | Efor: M | Rank: 60

## Ne
Add MessageActions.MoveToFolder(MailAccountData account, string folderFullName, IReadOnlyList<MailMessageSummary> summaries, string targetFullName) in MainProject/Services/Mail/MessageActions.cs, modeled directly on the existing Delete method: guard Protocol == Imap and !folderFullName.StartsWith(MessageStore.LocalFolderPrefix), remove the summaries from the RAM index immediately (optimistic), then on the connection task open the source folder ReadWrite and call folder.MoveToAsync([..uids], target) exactly like ImapSyncService.ExecuteRuleMovesAsync already does for rule moves (one batched call, not per-message). UI: a Move button on the existing bulk action bar in Mail.razor (next to bulk read/star/delete) that opens a popover listing MessageStore.GetFolders(account.Id) minus the current folder and Local/ folders, indented by IMAP hierarchy separator, with role icons for special folders. Clicking a target fires MoveToFolder, clears the selection, and shows the existing toast ("Moved 5 messages to Receipts").

## Neden
Multi-select shipped with read/star/important/delete but no move, which is the single most common triage action after delete. The exact MoveToAsync batching pattern already exists twice in the codebase (MessageActions.Delete for single, ExecuteRuleMovesAsync for batched), so this is a copy of proven plumbing plus one popover; no new architecture.
