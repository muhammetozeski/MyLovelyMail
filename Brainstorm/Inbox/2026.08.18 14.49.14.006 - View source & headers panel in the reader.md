# View source & headers panel in the reader

Kategori: reader-pane | Efor: S | Rank: 1

## Ne
Add a 'Source' SecondaryButton to the mail-reader-actions row in MainProject/UI/Pages/Mail.razor that opens a CoreModal with two tabs: a parsed header table and the raw MIME. In MainProject/UI/Pages/Mail.razor.Reader.cs add ShowMessageSource state plus a LoadMessageSource() that calls MessageStore.TryLoadMimeMessage(account.Id, folderName, open.Uid) for the header list (message.Headers, name/value rows) and MessageStore.TryLoadFullMessage for the raw text shown in a monospace <pre> (cap display at ~256 KB), with a copy button via Clipboard.Default.SetTextAsync. Styles go in MailCss.razor next to the existing mail-reader-* classes. Everything reads the already-cached .eml, so it works offline and needs no protocol code; when TryLoadFullMessage returns null show the same 'not cached yet' hint the body pane uses. Verify through the DebugApi (http://127.0.0.1:52539) by adding a /open-source endpoint in MainProject/zTests/DebugApi.cs that returns the same header list for the open message. Do NOT include a 'Save as .eml' button — a separate pending Brainstorm inbox idea (2026.08.17 16.13.14.316 - Save message as .eml or .html) covers export, and bundling it here would merge two concerns into one commit.

## Neden
A daily driver constantly needs headers to check the real Return-Path of a suspicious mail, the Received chain, or which server delayed a message — today the only way is digging the .eml out of UserCache by hand. All the data is already on disk via MessageStore (verified: TryLoadMimeMessage/TryLoadFullMessage at MessageStore.cs:255-272), so this is pure presentation, fully verifiable offline, and beats the List-Unsubscribe idea on value-to-effort since that one's end-to-end payoff needs a live external newsletter endpoint.
