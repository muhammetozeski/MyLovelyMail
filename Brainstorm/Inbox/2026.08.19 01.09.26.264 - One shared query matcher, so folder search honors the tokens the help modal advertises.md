# One shared query matcher, so folder search honors the tokens the help modal advertises

Kategori: search-filtering | Efor: M | Rank: 1

## Ne
In MainProject/Services/SearchService.cs, promote the private ParseQuery (line 48) to a public `BuildMatcher(string query) -> Func<MailMessageSummary,bool>` that ANDs the predicates and free-text tokens, plus `HasFreeText(string query)`; have the existing Search() call BuildMatcher so exactly one parser exists. In MainProject/UI/Pages/Mail.razor.cs replace MatchesSearch (lines 213-217, four literal Contains over Subject/FromName/FromAddress/PreviewText with the raw SearchText) with that matcher, so folder-scoped search understands from: to: tag: has:attachment is:unread is:starred identically to the all-folders path. Add `is:important` as one more case in the parser switch (MailFlags.Important = 64 already exists and the `I` key already toggles it). Change ConversationMode (line 137) from `string.IsNullOrWhiteSpace(SearchText)` to `!SearchService.HasFreeText(SearchText)` so a pure-token query does not silently flatten conversation grouping. Then add four toggle chips in the existing `.mail-search-tools` div of Mail.razor (lines 96-108) - Unread, Starred, Attachments, Important - each adding/removing its token in SearchText and reusing the existing `mail-search-toggle` / `mail-search-toggle--on` classes, so no new CSS is required. Split into separate commits: parser extraction + folder-search fix first, chips second. Verify with one new DebugApi route in MainProject/zTests/DebugApi.cs, `GET /list?accountId=&folder=&query=`, returning the uids that pass SearchService.BuildMatcher - the same function the page now calls - so a few curl calls prove token and chip combinations with no screen interaction.

## Neden
The shortcut help modal at Mail.razor.Interaction.cs:30 prints `from: to: tag: has:attachment is:unread is:starred` as a documented search language, but Mail.razor.cs:101 only routes through SearchService when the All folders toggle is on. In a normal folder view the query falls to MatchesSearch, which passes the whole SearchText as one literal substring, so `is:unread` matches zero rows and the app visibly breaks a promise it prints on screen. Collapsing to one parser is less code than the two filter paths that exist today, and the chips then ride on it for free: one click for unread, or unread plus attachments, which is the fastest way to cut a fat inbox down to the rows needing a decision.
