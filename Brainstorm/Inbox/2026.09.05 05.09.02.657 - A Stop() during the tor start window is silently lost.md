# A Stop() during the tor start window is silently lost

Kategori: resilience | Efor: S | Rank: 4

## Ne
TorProcess.StartAsync checks running under startGate, then finds the executable, picks a port and
calls process.Start() OUTSIDE the lock, assigning running only afterwards. A Stop() arriving in
that window sees running == null and returns.
Fix: record the pending start under the lock so Stop() can either wait for it or mark it
stop-requested and kill it as soon as it exists.
Also: if process.Start() throws the Process object is never disposed, and a dead Process in
running is overwritten by the next start without Dispose().

## Neden
The user presses "Stop the app tor" during the bootstrap; the button reports success and the tor
that appears a moment later keeps running. Harmless for routing - it is a real tor - but the
request silently did nothing.
