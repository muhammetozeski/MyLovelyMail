# Folder tree in the sidebar (parent/child from FullName)

Kategori: Folder hierarchy | Efor: M | Rank: 1

## Ne
Give MailFolderData the hierarchy it already receives and throws away. Add `char Delimiter`, set from MailKit's `folder.DirectorySeparator` at both folder save sites (ImapSyncService.SyncFolderListAsync around line 246, SyncOpenedFolderAsync around line 394). No legacy-inference machinery: SyncFolderListAsync re-saves every folder.json on every pass, so a folder written before this change carries Delimiter 0 only until the next sync — treat 0 as top-level and it heals itself.

Add `FolderTreeService.Build(List<MailFolderData>) -> List<FolderNode(Folder, Depth)>`, splitting FullName on that folder's Delimiter, and let it replace `SortFolders` at Mail.razor.cs:312 (both call sites, lines 69 and 110). RoleRank still orders the top level (Inbox first); children follow their own parent alphabetically. Folders under `MessageStore.LocalFolderPrefix` ("Local/") must NOT nest under a phantom "Local" parent — they stay one flat group keeping the existing `(this PC)` suffix.

The sidebar loop (Mail.razor:78-109) indents by a `--folder-depth` custom property; the move popover (Mail.razor:219-232) consumes the same node list so the ambiguity dies in both places at once. No collapse state, no collapse file, no unread rollup — that is a separate concern and it would reach into the shipped one-meaning unread badge.

Verifiable with no mail server: extend GET /folders (DebugApi.cs:348) with Depth/ParentFullName/Delimiter, add a `GET /folder-tree?probe=A/B,A/B/C,Local/Receipts` arm that runs the builder over handmade names (same hand-it-fake-input style as /start-folder?pretend=), and /dom?selector=.mail-sidebar to prove the indentation renders.

## Neden
MailFolderData has no parent and no delimiter, and DisplayName is set to `folder.Name` — the leaf. So a nested mailbox renders as a wall of same-level rows and two different folders show the identical label, in the sidebar AND in the move menu where picking the wrong one files mail somewhere the user did not mean. The app already admits this failure in its own comment at Mail.razor.cs:335-340 (the local-folder icon exists because "two rows showing 📝 Drafts are indistinguishable") — that patch covers only the local-vs-server case and leaves server-side nesting untouched. Every later hierarchy feature needs this parent link to exist first.
