# Local-only mail is exempt from the cache trimmer

Kategori: data integrity | Efor: S | Rank: 1

## Ne
In `OfflineCacheTrimmer.MeasureCachedBodies` (MainProject/Services/Mail/OfflineCacheTrimmer.cs:121) skip folders whose `MailFolderData.IsLocal` is true — `MessageStore.GetFolders(accountId)` returns local folders alongside server ones, so today every `Local/…` folder is in the deletion pool. Add `TrimReport.ProtectedLocalBodies` (count) and a `ProtectedFolders` list so the persisted receipt (`UserData/cache-trim.json`, surfaced by `GET /trim`) states the exemption instead of it being invisible. Verify through the existing `POST /trim-rehearsal` dry run: local folders must leave the dropped set while server folders still trim.

## Neden
`Drop`/`MessageStore.DeleteCachedBody` are written on one assumption, stated in DeleteCachedBody's own doc comment — "the row stays, and opening it downloads the body again" — which is false for `Local/Drafts`, `Local/Outbox`, `Local/Sent` (all written by `ComposeService.StoreInLocalFolder` with `IsLocal = true`) and every `MessageStore.MoveToLocalFolder` target: the .eml IS the message. `SyncScheduler.cs:113` runs `TrimAll()` after every sync pass, so both stages fire unattended once either budget is set. Age stage: `MoveToLocalFolder` copies the summary untouched apart from the re-keyed uid, so the message's original `DateUtc` rides along and mail deliberately filed into a local folder is destroyed on the next pass; a draft parked longer than the keep window loses its body, `ComposeService.LoadDraft` then returns null and `OpenMessageOrDraft` (Mail.razor.Reader.cs:333) falls through to the reader on an empty message. Size stage: it drops oldest-first across the whole account, and an Outbox message whose MIME it removes is then deleted outright by `OutboxService.FlushAsync` ("dropped '…' — its MIME file is gone", OutboxService.cs:164) — a message the user already pressed Send on, gone with a Warning-level log line.
