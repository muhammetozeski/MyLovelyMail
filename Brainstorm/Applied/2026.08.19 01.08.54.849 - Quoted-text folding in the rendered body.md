# Quoted-text folding in the rendered body

Kategori: reader | Efor: M | Rank: 1

## Ne
Add a fold pass to MailBodyRenderer.Render() that collapses trailing quoted history behind a CSS-only <details><summary>Show quoted text</summary> block, one path per branch Render() already has.

HTML branch: after Sanitize(), a new FoldQuotes(html) finds the EARLIEST index of any tail marker -- <blockquote, div class="gmail_quote", div class="moz-cite-prefix", div id="divRplyFwdMsg", <hr id="stopSpelling"> -- and splits the string there, emitting head + "<details class=\"mlm-quote\"><summary>...</summary>" + tail + "</details>". Do NOT attempt to detect a "top-level" container or balance tags: regex cannot balance HTML, and the existing Sanitize() already accepts that constraint. Only fold when the marker index is past a minimum head length (a message that is nothing but a quote should not collapse to an empty body).

Plain-text branch (currently $"<pre>{WebUtility.HtmlEncode(...)}</pre>"): split on the first line matching the attribution pattern ("On <date>, <who> wrote:" / "-----Original Message-----") or the start of a run of lines beginning with ">", encode both halves separately, and emit two <pre> blocks with the tail inside the <details>.

Styling goes into WrapDocument's inline stylesheet beside the existing blockquote rule, reusing AppColors.MailCanvas.QuoteBorder and QuoteText so the summary matches the quote color already there, plus summary{cursor:pointer;list-style:none} and a pill background. <details> toggles with zero JS, so the iframe at Mail.razor:424 keeps sandbox="allow-same-origin" with no allow-scripts.

Guard with public static readonly Setting<bool> FoldQuotedText = new(true) in the Reading block of Stores/Settings.cs. Note: Settings.razor has NO Reading section -- its sections are Appearance, Window & startup, Notifications, Sync, Composing, Filters, Data & migration, Diagnostics, Vault, Accounts. Add a new "Reading" settings-section-title with a CoreToggle bound through SetAndSave(GlobalSettings.FoldQuotedText, v), matching the CloseToTray row.

RenderedBody gains a QuotedTextFolded flag next to RemoteImagesBlocked (only two construction sites, both inside MailBodyRenderer). MessageExportService.ExportHtml passes foldQuotes:false so a saved/printed snapshot stays whole -- consistent with the allowRemoteImages:true it already passes for the same documented reason.

## Neden
Every reply in a real thread carries its whole history below it, so the reader opens on two lines of new text followed by three screens of yesterday. It is the highest-frequency annoyance in the reader and it is fixed inside one static class every body already funnels through -- no network, no protocol work, no new service, and it cannot touch sync.

Verified against the repo: Render() has exactly the two branches described; WrapDocument already emits the blockquote rule using AppColors.MailCanvas.QuoteBorder/QuoteText; Mail.razor:424 is sandbox="allow-same-origin" with no allow-scripts, which is precisely why a JS-free <details> is the right mechanism; and nothing matching details/gmail_quote/moz-cite/fold exists anywhere in the tree today.

It is also a pure string transform, so it verifies headless. DebugApi.cs:216 already returns bodyHtml = MailBodyRenderer.Render(account, folder, summary)?.Html from GET /message: drop a saved reply .eml into the local mock server, fetch it, assert <details class="mlm-quote"> appears and the new text stayed above it; toggle Settings.FoldQuotedText off, re-fetch, assert the marker is gone. Full round trip, zero screen clicks.

The one real risk is unbalanced tags on hostile marketing HTML, and it is contained: worst case is a visually odd body in a sandboxed iframe, in a renderer whose sanitizer is already regex-based by design.
