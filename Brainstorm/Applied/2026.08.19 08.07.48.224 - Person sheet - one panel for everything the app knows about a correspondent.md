# Person sheet: one panel for everything the app knows about a correspondent

Kategori: contacts | Efor: M | Rank: 1

## Ne
Add PersonProfileService (MainProject/Services/Mail/) that walks MessageStore.GetFolders + GetSummaries ONCE for a given address and returns a PersonProfile record: total messages, received vs sent (split on FolderRole.Sent, the same signal ContactIndexService.Build already weights at 3x), unread count, first/last DateUtc, per-folder counts, how many messages have HasAttachments, the tag names that landed on their mail, and the fullest FromName ever seen. CUT from the original proposal: (a) the 'other addresses' alias-candidate list built by matching FromName — FromName is sender-controlled and is the least trustworthy field in the header, so that list would collapse every Support/Info/Notifications/noreply sender into one fabricated human and present the guess as evidence; ship the profile keyed strictly on the address. (b) the mute action button — MuteService.MuteThread(account, folderFullName, summary) is conversation-scoped and persists Message-Ids in MutedThreadStore; there is no mute-a-sender path for that button to call, so it would need a whole new feature underneath it. Keep the rest as scoped: MailUiState.OpenPerson(string address)/ClosePerson beside the existing OpenCompose/CloseCompose pair, a mail-person-sheet panel in Mail.razor opened from mail-reader-avatar (line 447) and the mail-reader-history pill (lines 454-460), reusing AvatarGradient/AvatarInitials from Mail.razor.Interaction.cs, with buttons wired only to things that already exist: RunSavedSearch("from:"/"to:") and StartCompose. HistoryOfOpenSender (Mail.razor.Reader.cs:61-84) collapses into the service so the reader keeps its one-scan-per-uid caching and there is one scan instead of two. CSS in MailCss.razor using AppMeasures.Space/Font and AppColors. DebugApi gets GET /person?accountId=&address= returning the profile and POST /person/open?address= driving the same MailUiState call the avatar click makes, so every number is checkable without touching the screen.

## Neden
Verified the premise rather than taking it: the reader's SenderHistory record carries exactly three fields (MessageCount, UnreadCount, OldestUtc) and the pill renders those three before handing the user off to a from: search — nothing in the app aggregates anything else per human. Every field the profile needs is already in the RAM summary index that SearchService and ContactIndexService walk today (FolderRole, IsUnread, HasAttachments, Tags, DateUtc); none of it is gathered per correspondent. With the alias guessing and the orphan mute button removed, what is left is one service, one record, one panel and two endpoints, it deletes a duplicate scan out of the reader instead of adding a second one, and GET /person makes every count assertable through the DebugApi with no live mail server involved.
