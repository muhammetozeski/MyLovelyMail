# Attachment strip in the reading pane

Kategori: attachments | Efor: M | Rank: 30

## Ne
New static AttachmentService in MainProject/Services/Mail that opens the cached MIME file the same way MailBodyRenderer does (MimeMessage.Load on the MessageStore path) and returns a list of AttachmentInfo records (index, file name, MIME type, human-readable size) from message.Attachments. Mail.razor renders these as a chip row under the message header when summary.HasAttachments is true, each chip showing an icon chosen by extension/content-type (image, pdf, archive, doc, audio, generic) drawn from theme-consistent inline SVG. Clicking a chip calls AttachmentService.SaveAsync(index) which decodes the MimePart with DecodeToAsync into a target file; default target is the Windows Downloads folder with name-collision suffixing, plus a 'Save all' button that dumps every part into a subfolder named after the subject. A small toast/status line in MailUiState reports the saved path.

## Neden
HasAttachments is already tracked and the full MIME is already on disk, but the user currently has no way to see or extract attachments at all — this closes the largest remaining gap in reading mail, reusing the exact load path MailBodyRenderer already proved.
