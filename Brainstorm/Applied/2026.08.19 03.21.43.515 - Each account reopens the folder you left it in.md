# Each account reopens the folder you left it in

Kategori: Folder column usability | Efor: S | Rank: 2

## Ne
New `Stores/FolderMemoryStore.cs` in the `TagStore` shape (`UserData/folder-memory.json`, `AtomicFile.WriteAllText` + `JsonDefaults.Indented`, plain `Dictionary<string,string>` of accountId -> folder full name, plus one entry for the last selected accountId; no OnChanged event). Written from the folder click path, read in two places in `Mail.razor.cs`:

1. `SelectAccount` (line 66) currently ends with `var inbox = Folders.FirstOrDefault(f => f.Role == FolderRole.Inbox) ?? Folders.FirstOrDefault();`. Resolve the remembered full name against the already-materialised `Folders` list first, then fall back to that exact Inbox-then-first chain. The fallback is mandatory, not optional: `MailUiState.SelectFolder` ends with `if (folder is { IsLocal: false } && AccountStore.GetById(...) is { Enabled: true, Protocol: IncomingProtocol.Imap } account) ImapSyncService.KickFolderSync(account, folder.FullName);` — a renamed or server-deleted folder would put `SelectedFolder` on a phantom path and fire a sync at a folder that does not exist.
2. `TrySelectFirstAccount` (line 77) picks the remembered accountId via `AccountStore.GetById` before falling back to `AccountStore.Accounts[0]`.

Ctrl+1..9 inherits the fix for free — `Mail.razor.Interaction.cs:210` already calls `SelectAccount(AccountStore.Accounts[accountIndex])`.

Do NOT park this on `MailAccountData` + `AccountStore.Save`: that method writes account.json, logs `Account saved: ...` (AccountStore.cs:64) and raises `OnAccountsChanged` (:65), which `Mail.OnInitialized` subscribes to via `HandleStateChanged` -> `RefreshLists` — every folder click would emit a log line and re-render the page.

Verification goes through the DebugApi at 127.0.0.1:52539, no screen clicks: `GET /folders` already exists; add a small `POST /select-folder` (accountId + folder full name) and extend `GET /status` to report the selected account and folder, so the sequence select-folder -> select another account -> select back -> read status proves the restore, and pointing it at a bogus folder name proves the fallback lands on Inbox instead of kicking a sync at nothing.

## Neden
Hopping between accounts to answer one thread throws away your place in Archive or a project folder every single time, and restart always lands in account[0]'s Inbox. Restoring the folder also restores the on-demand sync that `SelectFolder` kicks, so the folder you actually work in is warm at startup instead of only the Inbox. Self-contained, one new store, two call sites, and the failure mode is explicitly handled.
