# The migration bundle carries accounts and rules in cleartext

Kategori: protection | Efor: M | Rank: 2

## Ne
ExportBundle zips every file under UserData as-is and adds one passphrase-encrypted
portable-vault.json. Everything else travels in the clear inside the zip: Accounts/<id>/account.json
(address, IMAP/POP/SMTP hosts, ports, usernames, the TorOnly flag), config.txt, filters.json, tags,
folder-memory.json.

Anyone holding a .lovelybundle - it gets emailed, left on a USB stick, synced to cloud backup -
opens it with any unzip tool and reads the account topology and every rule without the passphrase.
For a Tor-only account that file names the provider the account exists to keep private.

Fix: encrypt the whole bundle under the passphrase rather than one entry inside it, reusing the
AES-GCM + PBKDF2 that CredentialVault.ExportPortable already uses. Old bundles must still import,
so the reader has to accept both shapes and say which it found.

Also worth correcting in the same pass: the Settings hint reads "passphrase-protected passwords",
which is literally true and invites the reader to believe the bundle is protected.

## Neden
The feature is offered as the way to move to a new machine, so the file is made to be carried
around. What it actually protects today is the passwords alone.
