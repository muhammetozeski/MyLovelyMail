# Date tokens in the shared matcher (after:/before:/on:/newer_than:)

Kategori: search-language | Efor: S | Rank: 1

## Ne
Add date cases to the ParseQuery switch in MainProject/Services/SearchService.cs — today the switch has exactly five prefixes (from, to, tag, has:attachment, is:unread|starred|important|snoozed) and everything else hits `default: textTokens.Add(token)`. Add absolute `after:2026-08-01`, `before:…`, `on:…` and relative `newer_than:7d` / `older_than:2w|3m`, each pushing one predicate over MailMessageSummary.DateUtc (MailMessageSummary.cs:44). The detail that must be right: DateUtc is UTC while the typed date is what the user reads in the en-US-pinned list, so parse to local midnight and convert with DateTime.SpecifyKind(parsed, DateTimeKind.Local).ToUniversalTime(), and make `on:` a half-open [midnight, next midnight) range rather than a date-equality test. Unparseable values keep falling through to textTokens exactly as now, so the change stays purely additive and the separate `query.Contains("is:snoozed")` check in BuildMatcher is untouched. Then two one-line edits for discoverability: a ("🕒 Last 7 days", "newer_than:7d") entry in the QuickFilters array at MainProject/UI/Pages/Mail.razor.cs:220, and the new tokens appended to the ("Search", "from: to: tag: …") row at MainProject/UI/Pages/Mail.razor.Interaction.cs:30. Because BuildMatcher is the one matcher, the folder list, all-folders search, the quick-filter chips and DebugApi /list all gain it at once.

## Neden
Date is the most-used narrowing axis in a mailbox and it is the one operator the query language lacks — and its absence is worse than a plain gap, because a typed `after:2026-08-01` currently degrades into a free-text token searched against subject/from/to/preview/tags and returns zero hits with nothing explaining why. Relative forms also give a saved search a shape that survives a restart: `is:unread newer_than:7d` still means the same thing next month, while an absolute date rots. Verification needs no screen clicks — DebugApi already routes /list through SearchService.BuildMatcher with a `query` parameter (zTests/DebugApi.cs:461), so GET http://127.0.0.1:52539/list?accountId=…&query=newer_than:7d and a two-token range query cross-check against the DateUtc values from /messages.
