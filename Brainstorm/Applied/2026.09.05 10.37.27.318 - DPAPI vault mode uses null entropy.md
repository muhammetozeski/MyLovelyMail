# DPAPI vault mode uses null entropy

Kategori: protection | Efor: S | Rank: 2

## Ne
CredentialVault calls ProtectedData.Protect/Unprotect(plain, null, DataProtectionScope.CurrentUser).
With no entropy, ANY process running as that Windows user can decrypt vault.json - read the file,
base64-decode Payload, call Unprotect with null, and every mail password comes out in cleartext.
No master password involved.

A copied folder on another machine still yields nothing, so the machine-binding half is sound.
This is the price of the "unlocks automatically" design, but it does not have to be this cheap:
a per-install random entropy value stored beside the vault raises the bar from "any code as this
user" to "any code as this user that also read this file".

The deployed vault.json is Mode=0 (Dpapi) with an empty salt, so this is the path actually in use.

Fix: generate 32 random bytes on first use, keep them in UserData next to the vault, pass them as
optionalEntropy. Migration: try with entropy, fall back to null once and re-protect.

## Neden
The vault is the one file in the app that is supposed to be hard to read. Today a script running as
the user reads it in three lines.
