# Local folders get their own uid space

Kategori: data-integrity | Efor: S | Rank: 1

## Ne
MessageStore.MoveToLocalFolder (MainProject/Storage/MessageStore.cs:311) reuses the source folder's uid as the key in the target local folder. Verified: it calls SaveFullMessage(accountId, targetFullName, uid, mimeBytes) -> MessagePath writes Messages/<uid>.eml, then UpsertSummaries, which does `index.Summaries[summary.Uid] = summary` (line ~194). IMAP uids restart per folder, so filing INBOX uid 7 and Sent uid 7 into the same Local/Receipts overwrites the .eml and the index row, and CarryOverLocalState (line 208) first grafts the vanishing message's Tags/Important/Muted/Snooze onto the survivor. Both entry points reach it: the bulk picker (Mail.razor.Interaction.cs:178 keeps every local folder as a target from ANY source folder, server or local) and rules (ImapSyncService.ExecuteRuleMovesAsync line 380 passes the currently-synced folder.FullName, so rules on non-INBOX folders file into the same local folder). Fix: a local folder has no server, so its uid is only a local key -- allocate a free one. Inside MessageStore, before the upsert, check the target index for that uid under a different MessageId; if taken, derive a candidate from the message-id hash (the same spelling ComposeService.StoreAsMessageInLocalFolderAsync line 286 and Pop3Service.BuildSummary line 167 already use), and step to the next free number if that collides too. Keep the hash helper reachable without Storage calling up into Services/Mail -- Fnv1aHash currently lives in Pop3Service.cs:206, so move it to a shared spot rather than referencing a service from the store. Write the cached MIME to MessagePath(target, newUid) and set summary.Uid before UpsertSummaries; the collision check needs the private Indexes dictionary, so it belongs in MessageStore itself. The same guard covers ComposeService.StoreAsMessageInLocalFolderAsync, where two messages with no Message-Id hash separate Guid fallbacks today but share the local Sent/Outbox folder. Verify entirely offline through the DebugApi: POST /move (DebugApi.cs:686) a message from INBOX and one carrying the same uid from another folder into Local/Test, then GET /folders and confirm CachedCount is 2, and GET /read on both uids returns two different subjects.
