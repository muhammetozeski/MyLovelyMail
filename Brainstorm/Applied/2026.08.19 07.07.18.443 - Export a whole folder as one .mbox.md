# Export a whole folder as one .mbox

Kategori: export | Efor: M | Rank: 1

## Ne
New `MailboxExportService` in `MainProject/Services/Mail/`, next to `MessageExportService.cs` (which today is per-uid only). `ExportFolderMbox(MailAccountData account, string folderFullName)` takes `MessageStore.GetSummaries(account.Id, folderFullName)`, orders by `DateUtc` ascending, and for each summary pulls raw bytes with `MessageStore.TryLoadFullMessage(account.Id, folderFullName, summary.Uid)`, appending to a single file in mboxrd form: a `From MAILER-DAEMON <asctime>` separator built from `summary.DateUtc`, then the raw MIME with any body line matching `^>*From ` given one extra `>`. Destination reuses the helpers `MessageExportService` already calls (they are `internal static` in `AttachmentService.cs` at lines 101/108/117, same assembly): `AttachmentService.UniquePath(AttachmentService.DownloadsFolder(), AttachmentService.SafeFileStem(folderFullName, "mailbox") + ".mbox")`, so `Local/Archive` lands as `Local_Archive.mbox`. Messages whose body was never cached are counted, not silently dropped — return `(string Path, int Written, int SkippedUncached)` so the caller can report "412 of 480 messages, 68 bodies were never downloaded". Entry points: a button following the existing `mail-folder-action` pattern in the folder row at `Mail.razor:97` (where the mark-all-read control lives), routed through the existing `ReportSaveAsync` toast shell in `Mail.razor.Reader.cs:233` so success/failure text matches the other saves; and a new `case ("GET", "/export/folder")` in `MainProject/zTests/DebugApi.cs` beside the per-message `("GET", "/export")` at line 671, returning the same three fields. Verification without clicking: call `/export/folder?accountId=...&folder=INBOX`, count lines matching `^From ` in the written file and compare to `Written`, then re-parse the file with MimeKit's mbox parser (MimeKit ships with the MailKit 4.17.0 reference in `MainProject.csproj`, and `MessageStore.TryLoadMimeMessage` already uses it) and confirm the message count matches and no body was corrupted by the escaping.

## Neden
Nothing in the app moves more than one message at a time, and the migration bundle in `MainProject/Stores/MigrationService.cs` is the app's own UserData zip, not mail another client can read. A grep for mbox across the tree returns zero hits. mbox is what Thunderbird, Apple Mail and every archiver import, so this is the difference between the mail living in MyLovelyMail and the mail being the user's. It needs no protocol work: everything it writes is already on disk under `MessageStore.MessagePath`, and the counted-skip return keeps it from quietly lying about completeness.
