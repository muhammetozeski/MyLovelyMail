# Sandboxed HTML body rendering in the reader pane

Kategori: reading-experience | Efor: M | Rank: 20

## Ne
New static service MailBodyRenderer (MainProject/Services/Mail/MailBodyRenderer.cs) that loads the cached .eml via MimeKit (MimeMessage.Load on MessageStore.MessagePath(accountId, folderFullName, uid)), takes HtmlBody (falling back to TextBody wrapped in <pre>), and sanitizes it with a small regex/HtmlAgility-free string pass: strip <script>/<object>/<embed>/<base> tags, strip on* event attributes and javascript: URLs, and rewrite cid: image srcs to data: URIs built from the message's inline MimePart attachments. Mail.razor's mail-reader-body GlassCard then renders it as <iframe sandbox="allow-same-origin" srcdoc="@renderedHtml"> so message CSS can never leak into the app shell, styled via MailCss.razor with AppColors-matching border radius. The iframe gets a minimal injected <style> using neutral colors so plain messages still look lovely in both themes. Loading happens async in Mail.razor.cs when MailUiState.OpenMessage changes (subscribe to OnSelectionChanged), replacing today's PreviewText-only display.

## Neden
The reader currently shows only the 160-char PreviewText (Mail.razor line 148) — real HTML mail is unreadable. This is the single biggest jump in daily usability, and the sandbox attribute plus sanitizer pass gives safety without any JS library.
