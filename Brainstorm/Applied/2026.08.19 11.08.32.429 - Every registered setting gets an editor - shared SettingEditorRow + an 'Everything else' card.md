# Every registered setting gets an editor: shared SettingEditorRow + an "Everything else" card

Kategori: settings-coverage | Efor: M | Rank: 1

## Ne
Extract the reflected control block in AccountSettingsPage.razor (lines 80-106: bool -> CoreToggle, Enum -> select, int/string -> input, plus the .filters-remove reset button) into a shared SettingEditorRow.razor taking an ISetting and a save callback; the account page renders through it unchanged. Then add one final GlassCard to Settings.razor that walks SettingsManager.GetAllSettings() (dead API today - Stores/SettingsManager.cs:19, zero callers) and renders a SettingEditorRow for every key not in a hand-maintained RenderedKeys HashSet. Skip list: the internal keys WindowX/WindowY/WindowWidth/WindowHeight/SavedSearches/Theme, AND CredentialVaultMode - its card shows the mode as plain text with Switch buttons rather than a bound control, so a RenderedKeys set derived from "has a control" misses it, and a raw enum dropdown would flip the mode without the re-encryption that CredentialVault.SwitchToMasterPassword/SwitchToDpapi perform, costing every stored password. That surfaces the 13 settings with no global control: DownloadAttachmentsAutomatically, OfflineKeepDays, OfflineMaxCacheMb, MaxAttachmentTotalMb, MarkAsReadDelaySeconds, ConversationView, ExternalImages, DeleteAction, QuoteTrimLines, Pop3FetchLimit, NotificationSound, QuietHoursStart, QuietHoursEnd. While extracting, close the parse hole: AccountSettingsPage.SetValue calls ISettingSetup.LoadFromStr, which for InheritedSetting<T> runs Value = Setting<T>.ParseOrDefault(text, Parent.DefaultValue, Key) and hits the Value setter that sets IsOverridden = true - so typing 'abc' into a numeric override commits an override pinned at the shipped default and silently stops that account inheriting. SettingEditorRow parses first and leaves the value untouched when parsing fails, reusing the clamping shape already in Settings.razor (SetUiScale, SetBackgroundFolderRefresh).

## Neden
Quiet hours is the clearest case: NotificationService.IsInQuietHours is fully written, midnight-wrapping branch and all, and QuietHoursStart/QuietHoursEnd appear in no screen and not even in AccountSettings - so they are stuck at 0 == 0 and the feature can never fire. The global external-image policy (read by MailBodyRenderer:95) and the global delete behaviour (read by MessageActions:125) are likewise editable per-account but unreachable globally. The catch-all card makes that structurally unrepeatable: a field added to Settings.cs without a hand-written row shows up automatically instead of shipping invisible, and the failure mode of a stale RenderedKeys entry is a visible duplicate row, not another silent dead setting. Verifiable end to end through the DebugApi: add GET /settings (key, value, default, isDefault) and POST /settings/set?key=&value= hitting the same save path the component uses, set QuietHoursStart, then GET /dom on /Settings to confirm a control exists for every non-skipped key, that CredentialVaultMode has no dropdown, and that a bad value on a numeric key leaves the value and IsDefault unchanged.
