# Switchable From identity on a draft

Kategori: compose | Efor: M | Rank: 2

## Ne
Replace the static `<div class="mail-compose-from">From: <b>@draft.Account?.EmailAddress</b></div>` (MainProject/UI/Pages/Mail.razor:372) with a row of account chips (one per `AccountStore.Accounts`, tinted `account.ColorHex` with `AppColors.InkOn` ink, current one marked) calling a new `ComposeService.SwitchSendingAccount(draft, next)`. That method has three jobs the current code makes impossible: (1) swap signatures - `BuildNew/BuildReply/BuildForward` (ComposeService.cs:137/148/165) concatenate `SignatureBlock(account)` into `Body`, so switching must strip the old account's block at the RFC 3676 `SignatureDelimiter` ("\n\n-- \n", line 128) and prepend the new account's; (2) delete the orphan - `SaveDraft` files the autosaved draft into the *old* account's `Local/Drafts` under `DraftUid(draft)` and `DeleteDraft` only ever looks in `draft.Account`'s folder (lines 42/94), so a switch strands a stale copy in the first mailbox forever. IMPORTANT: do NOT call `DeleteDraft` for this cleanup - it also recursively deletes `AttachmentStageFolder(draft)` (ComposeService.cs:35), which is keyed by `DraftId` and shared across the switch, so it would destroy the staged attachments the draft still needs. Call `MessageStore.RemoveMessages(oldAccount.Id, LocalDraftsFullName, [DraftUid(draft)])` alone; (3) reassign `draft.Account` and re-save. Pair it with a `SendGuardService` check, since the guard list (SendGuardService.cs:48 `Inspect`) is where every send-time second-look already lives and stays a pure function of the draft: add `public const string SendingIdentityCode = "sending-identity"`, a `ComposeDraft.ArrivedAtAddress` field (ComposeDraft.cs) filled by `BuildReply` from the message's `ToAddresses`, and a warning when the draft's account address is not among them ("This reply leaves from a@x, but the mail arrived at b@y.") - the existing `Send anyway` button in the warning bar (Mail.razor:423) already handles the override. Verify without the screen: `POST /compose?accountId=A` (DebugApi.cs:732), a new `POST /compose/from?accountId=B` returning `{from, bodyPrefix}`, then `GET /messages?accountId=A&folder=Local/Drafts` (empty) and `?accountId=B` (one row) to prove the orphan is gone and the stage folder still holds its files; and `GET /send-check?accountId=B&arrivedAt=a@x.test` returning the `sending-identity` warning - that endpoint (DebugApi.cs:646) already builds a `ComposeDraft` straight from query values, so it needs one added line.

## Neden
`StartCompose` (Mail.razor.Compose.cs:116) and `StartReply` (Reader.cs:275, through the shared `WithAccountAndFolder` guard) both freeze `draft.Account` to whatever the rail had selected, and the pane renders it as unclickable text - so replying to work mail while your personal account is open sends from the wrong address with the wrong signature, and the only fix is to discard the draft, switch accounts, and retype it. The orphan-draft cleanup and the signature swap are the parts a naive picker would get wrong, and both are invisible until they bite.
