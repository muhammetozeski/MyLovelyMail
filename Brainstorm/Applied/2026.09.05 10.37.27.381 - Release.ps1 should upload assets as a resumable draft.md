# Release.ps1 should upload assets as a resumable draft

Kategori: resilience | Efor: M | Rank: 2

## Ne
gh release create with the assets attached is all-or-nothing: three runs in a row built both zips
(about eight minutes each) and then died on the upload - twice on DNS for uploads.github.com, once
on the local network aborting a 133 MB POST. Each failure threw away the whole build, and one of
them left a draft that gh could not delete because the same network was gone.

Fix, the pattern the scratchpad script already proved: create the release as a DRAFT with the notes
and no assets; upload each asset separately with retries and a growing delay; verify the asset
count; then flip draft=false. A failure then leaves an invisible draft holding whatever uploaded,
and re-running resumes instead of rebuilding. Pair it with the draft-collision check already in the
script so a leftover draft is resumed rather than reported as a collision.

Smallest asset first, so a flaky link proves itself cheaply before the 133 MB one.

## Neden
The release step is the last thing every loop turn does, and on a bad connection it currently costs
eight minutes per attempt and can leave a draft behind that blocks the next run.
