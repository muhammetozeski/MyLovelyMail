# ToSafeName lets a dot-named or trailing-dot server folder collide or climb

Kategori: resilience | Efor: S | Rank: 2

## Ne
ToSafeName keeps letters, digits, "-", "_", "." and space, and percent-encodes the rest - so "/"
is neutralised and slash traversal is not possible. But "." and space pass through.

Measured over real inputs: a server folder literally named ".." makes FolderCachePath resolve to
the ACCOUNT ROOT, so its folder.json and Messages land one level above Folders (still inside that
account cache - contained, not an escape). "INBOX." and "INBOX " both normalise to "INBOX" on
Windows, so two distinct server folders share one directory and clobber each other index.

Fix: reject "." and ".." as whole segments and percent-encode a trailing dot or space, in
ToSafeName itself so every caller inherits it. A malicious or merely odd IMAP server is the input
here, which is exactly the kind that should not decide a path.

## Neden
Contained today, but the encoder is the one place that is supposed to make a server-supplied name
safe to use as a directory, and it does not fully do that.
