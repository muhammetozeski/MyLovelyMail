# Offline outbox with reconnect flush

Kategori: resilience | Efor: M | Rank: 60

## Ne
New static OutboxService in MainProject/Services/Mail/OutboxService.cs reusing the local-folder pattern from ComposeService (MessageStore.LocalFolderPrefix + "Outbox", role like the local Drafts folder). ComposeService.SendAsync (line 156) wraps SmtpSendService.SendAsync in a catch for network/socket errors: on failure it saves the built MimeMessage into the local Outbox via MessageStore.SaveFullMessage/UpsertSummaries and shows a 'queued, will retry' toast instead of an error. OutboxService.FlushAsync iterates queued messages, rebuilds MimeMessage.Load from stored bytes, sends via SmtpSendService, deletes on success. Hook the flush into SyncScheduler's periodic loop (after a successful sync means we are online) and expose OutboxService.PendingCount + OnOutboxChanged so Mail.razor's sidebar shows the Outbox folder only when non-empty.

## Neden
Sending while Wi-Fi is down currently just throws; users lose the mail or must keep the compose pane open. The whole local-folder persistence machinery (Drafts) already exists, so the queue is mostly reuse.
