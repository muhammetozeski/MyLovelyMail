# "Try it" — dry-run a rule against the cache before saving, with per-condition hit counts

Kategori: filter-rules | Efor: M | Rank: 1

## Ne
Promote `RuleEngine.Matches(FilterRule, MailMessageSummary)` (private today, RuleEngine.cs:55) to public and add `RuleEngine.Preview(FilterRule rule, int sampleSize)`. It walks `MessageStore.GetFolders(accountId)` x `MessageStore.GetSummaries(...)` for the rule's account — or every account when `rule.AccountId` is empty, mirroring the account gate at RuleEngine.cs:44 — and returns `{ scanned, matched, perCondition[], sample[] }`.

Hard constraint: Preview is READ-ONLY and must never call `ApplyActions`. `MessageStore.GetSummaries` returns `[.. GetIndex(...).Summaries.Values.OrderByDescending(s => s.DateUtc)]` (MessageStore.cs:179-180) — a fresh list of the *stored* instances out of the folder index's `ConcurrentDictionary<uint, MailMessageSummary>` — so calling `ApplyActions` would really mark-read/tag/flag/mute the user's cache. The preview renders action types as text only.

The payoff is `perCondition`: each `FilterCondition` gets its own hit count over the same scan (free — `MatchesCondition` is already per-condition), plus an `operatorIgnored` flag for the three silent traps that exist in the code today: `HasAttachment` never reads `condition.Operator` (line 66), `SizeKb` collapses every non-`LessThan` operator to `>` (line 72), and `GreaterThan`/`LessThan` on a text field falls through to `_ => false` (line 93) so it can never match.

UI: a "Try it" `SecondaryButton` next to Save in the editor card at FilterRules.razor:85-88, rendering "matches 14 of 2,310 cached messages" plus the newest ~10 subjects and a red per-condition line for any condition with 0 hits.

Verification (must not require an on-screen click): add a `GET /rule-preview?ruleId=` case to the `(method, path)` switch in `MainProject/zTests/DebugApi.cs`, next to the existing `GET /dom` (:191) and `POST /navigate` (:198), returning the same `{ scanned, matched, perCondition[] }` payload; then `POST /navigate` to `/Settings/Filters` and `GET /dom` to confirm the panel rendered. Cap the scan (a bounded message count) so a large cache cannot hang the UI thread.

## Neden
The editor can only Save. A rule that matches nothing and a rule that matches everything look identical until real mail arrives — and by then `MoveToRemoteFolder` has already run `folder.MoveToAsync(...)` on the server (ImapSyncService.cs:387), which this app cannot undo. Thousands of messages already sit on disk in `index.jsonl`, the exact shape the engine matches against, so the question can be answered before the rule is ever armed. Per-condition counts turn "my rule doesn't work" into "condition 2 has 0 hits", which no current surface can answer, and they make the three operator/field mismatches visible instead of silent.
