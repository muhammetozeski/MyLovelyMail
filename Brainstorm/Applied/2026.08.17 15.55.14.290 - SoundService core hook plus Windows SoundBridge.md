# SoundService core hook plus Windows SoundBridge

Kategori: sound-design | Efor: M | Rank: 50

## Ne
Add a static SoundService in MainProject/Services (mirroring the NotificationService.Presenter pattern): `public static Action<string>? Player;` and `Play(string soundName)` that no-ops on null/"none" and logs via Logger. In the MAUI head add MyLovelyMail/SoundBridge.cs (next to NotificationBridge.cs), registered from MauiProgram/App startup like NotificationBridge.Initialize(): under #if WINDOWS it maps a sound name ("success", "spin") to the bundled MauiAsset via `FileSystem.OpenAppPackageFileAsync($"Sounds/{name}.wav")` copied once to AppDataDirectory, then plays it with a cached Windows.Media.Playback.MediaPlayer (Source = MediaSource.CreateFromUri(file path)). Unknown names fall back to success.wav; every failure is caught and logged, never thrown.

## Neden
spin.wav and success.wav ship as MauiAssets today but nothing in the codebase ever plays them; a one-file platform bridge with the exact hook pattern already proven by NotificationService.Presenter makes audio available to all of MainProject without any UI-layer JS or external libraries.
