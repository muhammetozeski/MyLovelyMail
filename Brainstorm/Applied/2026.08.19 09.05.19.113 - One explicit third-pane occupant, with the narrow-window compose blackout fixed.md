# One explicit third-pane occupant, with the narrow-window compose blackout fixed

Kategori: Layout | Efor: M | Rank: 1

## Ne
Add `MailUiState.ThirdPane` (Reader/Compose/Person, nullable) alongside the existing OpenMessage/ActiveCompose/OpenPersonAddress fields in MainProject/Services/MailUiState.cs. Set it in OpenCompose (line 26), OpenPerson (35) and OpenMessageInReader (110); in CloseCompose (47), ClosePerson (41) and CloseMessage (118) fall back to whichever other occupant still exists rather than clearing blindly. SelectAccount (62) and SelectFolder (70) already null OpenMessage, so they must drop ThirdPane to the next survivor too — otherwise the pane points at a message that is gone. First and load-bearing part: MainProject/UI/Pages/Mail.razor:11 computes `mail-screen--reading` from `OpenMessage != null` only, while MailCss.razor:1498-1515 hides `.mail-reader` below Breakpoint.TwoPane (980, AppMeasures.cs:117) except under that class. The sidebar Compose button (Mail.razor:20 -> StartCompose, Mail.razor.Compose.cs:154) only sets ActiveCompose, so on a window under 980px the compose card renders inside a display:none column and NoteComposeActivity's 3s timer autosaves a draft the user cannot see. TrayService.cs:125 allows windows down to 400px and restores saved bounds, so this is reachable. Rename the class to mail-screen--pane-open and compute it from `ThirdPane != null`, updating the one CSS selector at MailCss.razor:1507. Second part: Mail.razor:344 renders the person sheet unconditionally at the top of the same scrolling section as the reader body, so an open sheet pushes the message below the fold. Render exactly one occupant under a small tab strip listing only the occupants that exist, each with its own close button; switching tabs only moves ThirdPane, so the draft object, OpenMessage and OpenPersonAddress are untouched. Verify through the existing DebugApi (zTests/DebugApi.cs): `POST /compose` (line 811) with no message open, then `GET /dom?selector=.mail-screen` (193) to see mail-screen--pane-open on the root and the compose card present; `POST /person/open` (298) to add a second occupant, then `GET /dom` again to confirm one occupant renders and the strip lists two; `GET /outbox` plus the draft file to prove the draft body survived. No new endpoint needed.

## Neden
The third column is the only place three different things can live, and its single visibility switch only knows about one of the three. Compose and the person sheet both arrived after the pane was designed, which is why the narrow-window rule still asks about OpenMessage — and why the sidebar Compose button walks straight into a silent blackout that still writes to disk. Making the occupant explicit fixes the blackout, the stacking, and the silent replacement in one change, using state that already exists.
