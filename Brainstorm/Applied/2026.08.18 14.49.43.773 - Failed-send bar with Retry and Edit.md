# Failed-send bar with Retry and Edit

Kategori: failure-recovery | Efor: S | Rank: 2

## Ne
In MainProject\Services\Mail\OutboxService.cs, RunSendAsync's catch currently only logs and fires a transient toast; additionally store a FailedSend record (Draft, error message, DateTime) in a new OutboxService.LastFailure property, add RetryFailed() (re-Enqueue) and DismissFailed(), firing the existing OnChanged. In MainProject\UI\Pages\Mail.razor, next to the undo bar block at line 208, render an error variant of .mail-undo-bar when LastFailure != null: "Send failed: <subject> — <reason>" with Retry, Edit (MailUiState.OpenCompose(draft) then DismissFailed), and Dismiss buttons; handlers go in MainProject\UI\Pages\Mail.razor.Compose.cs, styles extend .mail-undo-bar in MainProject\UI\Pages\MailCss.razor (line 697+). Verify via zTests\DebugApi.cs: POST /send with queued flag against a bad SMTP host, then a small GET /outbox endpoint exposing LastFailure, plus /outbox/retry.

## Neden
A queued send that fails after the compose pane closed surfaces only as a toast that vanishes; the mail sits silently in Drafts and the user must rediscover it and resend by hand. A persistent bar with Retry/Edit makes the failure impossible to miss and recovery one click, reusing the undo-bar pattern that already exists.
