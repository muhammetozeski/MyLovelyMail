# Snooze: hide a message until it is due, wake it unread

Kategori: deferral | Efor: M | Rank: 1

## Ne
Add `DateTime? SnoozedUntilUtc` to `MainProject/DataModels/Mail/MailMessageSummary.cs` — index.jsonl round-trips it through `JsonDefaults.SingleLine` (MessageStore.cs:168/228) and old lines deserialize as null, so no migration. New `MainProject/Services/Mail/SnoozeService.cs`:

- `Snooze(account, folderFullName, summary, DateTime untilUtc)` — sets the field AND calls `MessageActions.SetRead(..., read:true)` before `MessageStore.UpsertSummaries`. The SetRead is REQUIRED, not optional: `MessageStore.RefreshUnreadCount` (MessageStore.cs:201) counts `index.Summaries.Values.Count(s => s.IsUnread)` over the whole index, so a hidden-but-unread message would still inflate `folder.UnreadCount` and the `AccountUnreadCount` badge would point at mail the user cannot see.
- `Wake(...)` — clears the field and calls `MessageActions.SetRead(..., read:false)` so it returns as new mail.
- `WakeDue()` — walks `MessageStore.GetFolders` / `GetSummaries` for expired entries.

Call `WakeDue()` from `SyncScheduler.SyncNowAsync` at the `OutboxService.FlushAsync` call site (SyncScheduler.cs:105) — the existing periodic tick, no new timer.

Hiding must cover BOTH list paths. `RefreshLists()` in `Mail.razor.cs` returns early at lines 101-108 through `SearchService.Search` for all-folders mode, so filtering only the folder branch (line 119) leaks snoozed mail back into search hits; drop snoozed summaries in both, unless the query contains `is:snoozed`. Add `case "is" when value.Equals("snoozed", ...)` to `SearchService.ParseQuery` (following the SearchService.cs:87-95 pattern) so a `("💤 Snoozed", "is:snoozed")` entry appended to the existing `QuickFilters` array (Mail.razor.cs:192) is the entire filter UI.

Snooze button with fixed presets (+3h / tomorrow 08:00 / next Monday 08:00) in the `mail-bulk-bar`, reusing the `ShowMovePicker` + `.mail-move-popover` pattern, plus the same button in `mail-reader-actions`; a `mail-row-snoozed` chip in `mail-row-preview` shows the wake time. DebugApi gets `POST /snooze?accountId=&folder=&uid=&minutes=`, `POST /snooze/wake` and `GET /snoozed?accountId=`.

## Neden
Deferring a message is the one triage move the app cannot make today: the only alternatives are leaving it unread or `MessageActions.MoveToLocalFolder`, which pulls the message out of the synced folder permanently. Storing it as a summary field rather than a folder move means POP3, IMAP and local folders behave identically and no server round-trip can fail. Because the feature hides mail, the escape hatches are part of the build, not extras: the `is:snoozed` quick filter, the per-row wake-time chip, and `GET /snoozed`. Verification is fully offline through the DebugApi — snooze a uid, `GET /list` no longer shows it while `GET /list?query=is:snoozed` does, the folder unread badge does not move, `POST /snooze/wake` puts it back unread, and the value survives a restart in index.jsonl.
